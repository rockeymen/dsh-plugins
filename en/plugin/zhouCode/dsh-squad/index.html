Project overview

发送方可以为每项任务提出一种执行方式；未指定时默认使用最保守的完全人工决定。这只是对工作流的请求，不是远程授权：发送方不能借此提高权限，是否自动启动始终由接收方自己的成员/Peer 策略、本机自动执行规则以及 DSH Permission/Approval 决定。 执行方式 · 接收方看到的流程 · 系统强制的人类边界 执行方式: 完全人工决定 · 接收方看到的流程: 任务始终先等待接收方接受；接收方可以执行，也可以填写原因后拒绝或打回 · 系统强制的人类边界: 接受前 Agent 不启动 执行方式: Agent 辅助执行 · 接收方看到的流程: 获得本机授权后，Agent 先完成可安全处理的前置工作，需要判断时创建 HumanTodo · 系统强制的人类边界: 至少经过一次本地人工判断或最终结果审核，结果才发给对方 执行方式: Agent 全权执行 · 接收方看到的流程: 仅在匹配本机规则或接收方已将发送方设为完全信任时自动运行，否则仍等待本人接受 · 系统强制的人类边界: 不允许静默转成人工待办；需要人类判断时以明确失败结束

taskType 是双方约定的小写稳定标识，例如 release-notes。它只帮助接收方的 SAFE 规则精确匹配任务类型；类型、完整目标、附件条件和本机工具/资源限制必须同时匹配，单凭发送方填写的类型绝不产生权限。TRUSTED 会跳过规则匹配，属于接收方主动授予的高风险本机设置。

拒绝任务时必须填写原因。发送方可以据此修改并重新派发；Squad 会创建一个新的签名任务并记录 revisionOfDelegationId，原任务及拒绝原因保持不可变。辅助模式中，如果 Agent 未曾请求人工判断就直接准备好结果，结果会先留在接收方本机，接收方可以批准、让 Agent 在同一 Session 中修改，或拒绝任务。

dsh plugin --profile web add github:zhouCode/dsh-squad
