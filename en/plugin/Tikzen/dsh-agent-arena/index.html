Project overview

直接选择已经配置好的 AI 用户，创建长期协作会议，而不是重复填写 provider 和 model。 v0.3.3 布局修复 超长会议标题现在会在可用宽度内显示省略号，不会再把右侧协作栏或底部人类操作区挤出屏幕。 桌面端右侧协作栏支持拖动调整宽度，窄屏自动采用上下布局。 人类提示、点名栏、输入框和会议操作按钮始终保持在可视区域，长文字可以正常换行。 v0.3.2 更新速览 可自定义队列速率：同渠道每分钟放行次数不再固定为 55，可在协作设置中填写 1–10000。 可自定义冷却错误码：默认使用 429、500，支持添加或删除；也能识别部分中转服务把真实 429 包装成 500/getchannelfailed 的情况。 更干净的错误展示：空响应自动重试一次，连续为空时静默；其他运行错误移到右侧角色动态栏标红，不再占用聊天区。 v0.3.1 补丁

这次更新主要解决多个 AI 共享供应商渠道时容易触发限流，以及自动接话判断消耗较多 Token 的问题，新增以下三个可选配置： 渠道限流冷却选项：同一供应商配置命中用户设置的错误码后，相关角色会统一等待，并优先采用提供方返回的重试时间。默认错误码为 429、500，可以自行添加或删除。 同渠道请求队列选项：同一供应商下的正式发言、接话判断、工具续跑、子 Agent、重试和失败请求统一纳入队列。每分钟放行次数可在协作设置中自定义，默认 55；高并发时回复速度可能降低。 自动接话判断选项：管理员面板提供自动接话总开关；每个 AI 用户还可以单独关闭自己的判断请求，改由管理员直接判断是否适合接话。这样可以在保留连续讨论体验的同时，由用户自行控制额外 Token 消耗；关闭总开关不会影响人类发言和明确 @AI。

Arena 不读取或保存 DSH 中的 API Key，因此共享渠道按“供应商配置”识别：同一供应商配置下的不同模型会共用队列和冷却，分别配置的供应商则互不影响。

dsh plugin --profile web add github:Tikzen/dsh-agent-arena
