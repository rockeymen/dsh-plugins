项目简介

Runbook 故意不是文件浏览器、第二个聊天记录或 魔术项目总结。这是事实之上的一个小投影层 存在于DSH、Git、项目文档和观察文件中。 中心思想

工作单元不是新文件夹或文件名（例如 finalv7）。 研究意义·运行手册投影·真相来源 研究意义：我们要决定什么？ · 运行手册投影：问题/决策/开放问题指南针 · 事实来源：作者 README.md 和 STATUS.md 研究意义：我们能改变什么？ · Runbook 投影：稳定尝试单元 · 真相来源：脚本路径及其当前的 Git 工作树 研究意义：发生了什么？ · Runbook 投影：执行历史记录 · 事实来源：DSH 运行事实和会话沿袭 研究意义：它产生了什么？ · Runbook 投影：证据生成 · 事实来源：观察到的输出路径、元数据和可选哈希 研究意义：这是哪个版本？ · Runbook 投影：分支、提交和代理作者 · 事实来源：Git

1. 在 DSH 对话中打开 Runbook / 运行本。 2. 在打开长长的证据线索之前先阅读指南针。 3. 改进现有Attempt单元，当问题相同时；开始一个 仅当问题、数据、环境或输出契约满足时才创建新分支 真正不同。 4. 运行整个支持的入口点，检查计划并确认。 5. 将新证据与前几代证据和当前证据进行比较 谈话的转折产生了它。 6. 将有意义的检查点保存到 Git。代理可以编写自己的提交； 人类集成者可以仍然是提交者。 投影是如何构建的

dsh plugin --profile web add github:zhan-tz/dsh-plugin-runbook
