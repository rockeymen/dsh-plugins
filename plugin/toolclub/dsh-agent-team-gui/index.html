项目简介

随后打开 Settings → 小队 创建小队，在对话输入框旁选择它并开启小队模式。插件直接复用 dsh 已配置的模型路由和凭据存储，绝不会保存 API key。 你会得到什么 · 为什么有用 你会得到什么: 每个 Agent 独立的 provider/model 与工具策略 · 为什么有用: 一个小队可组合强规划、快实现和严审核模型 你会得到什么: 全局持久化的 Agent 与小队 · 为什么有用: 建一次队伍，即可跨项目、跨对话复用 你会得到什么: 固定顺序或主 Agent 动态编排 · 为什么有用: 固化可重复流程，或让当前对话的主 Agent 为每次任务安排所有成员 你会得到什么: 串行/并行执行与 spawn/fork/chain 上下文 · 为什么有用: 按任务选择协作拓扑，不被单一模式限制 你会得到什么: 实时运行中心与官方 token 用量 · 为什么有用: 查看规划、输出、重试、失败，以及每个成员由 provider 上报的真实 token

如果它确实解决了你的工作流，点一个 GitHub Star 能帮助更多 DeepSeek Harness 用户发现它；也欢迎提交真实小队配方和问题反馈。 [!WARNING] dsh 与本插件目前都是 developer preview。本插件面向 dsh >=0.1.0-rc.5 Node.js 22.19 或更高版本。dsh 在稳定版之前可能有破坏性变更；需要可复现时请同时锁定 dsh 与本插件版本。 核心差异

小队不必共享同一个模型配置。每个 Agent 都能独立选择 dsh 中已有的 provider/model 路由、 maxTokens 和工具 allow/deny 策略；这些 Agent 在 Settings 中保存为全局可复用定义，再组合为持久 小队。每个对话可选择一个小队并开启协作；开启后，普通的“发送”就进入协作流程。小队可固定成员 顺序；未固定时，由主 Agent 根据成员特性，为每名已配置成员生成专属分工与执行顺序。 状态与架构
