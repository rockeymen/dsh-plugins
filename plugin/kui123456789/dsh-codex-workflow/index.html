项目简介

DeepSeek Harness 插件赋予 Codex 只读计划/审核角色，而 DSH 仍然是唯一的执行者。两个流程共享相同的工作流引擎： Codex 主导的桥（首选） — 生成计划的 Codex 任务通过持久的 SQLite 桥将其发送到确切的实时 DSH 会话； DSH 实现了它，插件以只读方式验证源任务，并启动单独拥有的 Reviewer 任务，其结论返回到原始 DSH 会话以进行修复或签核。 DSH 主导的工具（旧版，仍受支持） — DSH 代理像以前一样驱动 codexworkflowstart / codexworkflowreview。

pnpm run lifecycle:accept 针对您的 Codex 应用程序服务器运行真正的审阅持久性验收（需要登录）：持久审阅者完成结构化判决轮次，托管应用程序服务器关闭，新的应用程序服务器重新读取轮次并验证其是否已持久保存为 completed 及其最终助理消息 - 然后同一审阅者恢复进行第二个已完成的轮次。 （在支持比较实验中，测试的终止和 EOF 关闭序列都读回已完成的回合及其最终消息，因此此回归验证了测试的序列，而不是证明根本原因。）该插件会优雅地关闭应用程序服务器（标准输入 EOF，然后仅在超时时升级到 SIGTERM/SIGKILL）作为防御性生命周期强化，以降低突然关闭与应用程序服务器的最终推出写入竞争的风险。 Codex 主导的流程（首选）

桥接器解析确切的会话（显式 --dsh-session 获胜；否则 cwd 必须精确匹配一个实时会话，并且歧义性会严重失败）。 DSH 将计划作为插件中继消息接收并实施。完成后，DSH 调用 codexworkflowsubmit；该插件将准确存储的 Codex 任务 ID 视为不可变源，验证其只读，并要求其托管应用程序服务器创建一个新的持久 Reviewer 任务：
