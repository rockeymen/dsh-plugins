项目简介

打开 设置 → 密钥轮换，并为每个提供程序列出其密钥的凭证名称。该插件将其存储在 dsh-key-rotation 设置命名空间中（与 settings.yaml 相同的位置）。 settings.yaml 字段·默认值·描述 字段：switchCodes · 默认：[QUOTA, RATELIMIT, SERVER, TIMEOUT, TRANSPORT, EMPTYRESPONSE, UNKNOWNMODEL] · 描述：触发按键开关的错误代码。 字段：cooldownMs · 默认：60000 · 描述：耗尽的钥匙保持不旋转的时间。 字段：providers · 默认：— · 描述：[{ provider, keys: [envName, ...] }]。 keys 是凭证/环境 名称，而不是键值本身。 密钥如何存储

插件配置仅通过 名称 引用键（例如 MYPROVIDERAPIKEY）。这些值存在于 dsh Credentials 服务或 $DSHHOME/.credentials.yaml 中 - 绝不存在于插件配置中。

输入到密钥轮换卡中的密钥将被写入同一凭证存储中：该值会传输到主机一次，并且永远不会发送回浏览器。只有最后 5 个字符是，因此可以在 UI 中区分两个键。启动环境提供的密钥显示为只读，因为在这里覆盖它无论如何都会被隐藏。 它是如何工作的 插件修补 ctx.credentials.resolve，以便池引用解析为当前健康密钥（循环，跳过冷却中的密钥）。 它拦截 llm/stream 以在可切换失败后重试下一个键的请求，而不是向调用者显示错误。这个钩子故意不是 async：循环直接迭代其结果，并返回一个承诺，每次都会中断。 提供者身份永远不会改变——只有解析的密钥会改变——这使得适配器的重放状态在多次调用过程中保持一致。

安装命令

dsh plugin --profile web add github:GooDAnDReaDY/dsh-key-rotation
