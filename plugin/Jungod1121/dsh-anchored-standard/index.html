项目简介

V4 Pro 的能力上限并不低——但它走哪套推理策略，是由第一次 API 请求给它看到的东西决定的。社区评测 xiaobright/modeltest 实测： 预设 · 首轮看到 · 全程可用 · Project2 V4.1b（max） 预设: Standard · 首轮看到: 25 工具 + 长 prompt · 全程可用: 25 工具 · Project2 V4.1b（max）: 91 / 92 预设: Minimal · 首轮看到: 一句话 prompt + 2 工具 · 全程可用: 只有 2 工具 · Project2 V4.1b（max）: 99 / 96 —— 但干不了完整开发 预设: 锚定标准 · 首轮看到: 一句话 prompt + 2 工具 · 全程可用: 全部 25 工具 · Project2 V4.1b（max）: 98 / 99

增益来自首轮轨迹锚定，而不是全程限制工具数量。这个预设给 V4 Pro 保留了 Minimal 的"脑子"（开局策略），同时还它 Standard 的"手脚"（完整能力）。 工作机制

1. 会话的第一条用户消息决定锚的类型： 任务 · Persona · 首轮工具 任务: spec — 修复 / 维护 / 调试 · Persona: Minimal 原句 · 首轮工具: bash + read + edit 任务: react — 从零构建 / 新项目 · Persona: 实干者句（少废话、直接产出） · 首轮工具: bash + read + write 任务: weak — 语义模糊 · Persona: 模型自分类（Pro：分类指令版） · 首轮工具: bash + read
