#dsh-plugin-turn-memory

DeepSeek Harness 的粒度上下文记忆：两步的第一步
上下文压缩计划。

当顶级（根或恢复的分叉）会话的回合完成时，该回合仅标记为待处理 - 否
摘要尚未运行。在下一轮，运行时上下文携带一个挂起的
通知和主代理本身 - 当前上下文，以及用户的新上下文
message in view — 组成上一回合的全回合检查点
遵循捆绑的 dsh-紧凑转弯技能，然后用
Compact_turn（转弯，摘要）。替换覆盖转弯的跨度开始
就在它自己的启动用户消息之后 - 该消息逐字保留
表面，因此检查点永远不会重复它，并将消息引导到内部
Span 逐字保留在自己的 <user-steer> 元素中。最新用户
消息总是逐字保留。一发叉子（与对话同款，分享它的温暖
请求前缀）只在主代理出现时写入摘要作为后备
在整个回合中留下未总结的回合。原始事件保留在
用于重放和调用的仅附加日志。

Expand_turn 工具以两种模式调用回合的完整记录：

- 代理 - 模型提出问题并按回合回忆路线
  年龄：最近的回合（在recallRecentWindowMs内结束，默认2小时）使用a
  其上下文逐字重播已完成回合的分叉 — 目标
  转弯的完整原始文本已经在该上下文中，并且叉子是
  仅当提供商的磁盘缓存仍保留前缀单元时才便宜
  当这些转弯运行时坚持；较旧的回合使用子代理，其中
  便宜的模型读取回合的全文并回答目标
  问题。
- raw — 该回合的全文直接返回到对话中；
  非常大的转弯被截断；当代理回答时的后备
  需要全文。

默认模式为代理模式；时间路由是工具内部的。

Compact_turn 工具可让模型在长时间转动过程中主动压缩：
它取代了当前回合的已完成部分（该回合之后的所有内容）
回合开始消息，直到当前步骤），带有一个检查点，保持
逐字启动消息和当前步骤。与可选的
转参数它压缩了完整的前一个转整体 -
span 在该回合自己的起始用户消息之后立即开始，该消息保持不变
表面上逐字逐句；这是待处理通知要求拨打的电话。的
检查点文本由当前上下文本身组成 - 组成
规则存在于捆绑的 dsh-compact-turn 技能中，文本到达为
该工具的摘要参数 - 因此没有分叉或子代理来总结跨度。
对于当前转动模式，工具验证范围（工具对
平衡），独占运行，并折叠跨度本身：收缩检查
（检查点字符与折叠节点模型可见文本），检查点
追加和表面替换都在插件中运行，镜像
全轮路径——不涉及压缩后端。全回合模式
重用与后备叉相同的替换路径（转弯记忆标记
检查站）。会话压缩保留了自己的廉价模型摘要器；的
两者永远不会混合。

有条件的尾部提醒会支持它：一旦当前回合跨越更多
比reminderNodeThreshold面节点数（默认30，按节点数计算，不
令牌），上下文结束运行时快照带有一条稳定的线路微移
面向compact_turn的模型；在 1.5 倍阈值时，该线升级为
直接警告。低于阈值时，提醒不会产生任何影响 - 零
令牌，零噪音——一旦压实落地，它就会自行消失。

## 摘要格式（版本 4）

每个检查点都是一条用户消息，其正文是角色序列
按照事情发生的顺序进行标记 - 没有根包装器（表面已经
将记录包装为回合摘要）：

    <user-steer>逐字引导消息</user-steer>
    <working>消息之间的处理，就地压缩</working>
    <assistant>面向用户的输出，逐字</assistant>
    <工作>…</工作>
    <助理>...</助理>

标记规则：

- 事后诸葛亮是用自然语言编写的，而不是括号标签：当稍后
  开发证明早期条目有误，已注释更正
  内联在出错的地方 - “我认为 X 可能会起作用。（后来
  结果是错误的。）”——并保留在其修改的条目旁边。假设
  按当时的感受表述；后来的更正是
  比早期条目具有权威性。
- 任何有关当前上下文的直觉都会被逐字保留：
  用户的措辞和强调、助理自己的承诺和提议，以及
  后面的任何措辞都可能会提到——加上命令，
  路径、标识符和错误字符串。
- 检查点保持原始顺序，没有根包装器（
  表面已经将记录包装为回合总结）：回合开始
  用户消息在检查点之前逐字保留在表面上，并且
  永远不会出现在里面；跨度内的每个转向消息都会保留
  逐字记录在其自己的 <user-steer>...</user-steer> 元素中，每个
  面向用户的助手文本输出保持原样
  <assistant>…</assistant> 元素位于其原始位置，并且仅
  中间过程（推理、工具调用、工具结果、例程
  检查）被压缩到 <working>...</working> 元素中。的
  元素按照事情发生的顺序交替——用户可以控制
  在回复之间，助理可以交替工作和聊天——
  并且标签本身标记了说话者，所以没有
  “用户：”/“助理：”/“进程：”前缀，无对话/摘要标签，
  没有单独的部分。检查点读起来就像对话本身
  随着流程的缩短。
- 结构标签仅出现在检查点文本内 - 从不出现在实时中
  对话输出——并且撰写摘要是无声的：文本是
  直接进入compact_turn摘要参数，并且永远不会打印为
  聊天，因此摘要过程根本不会产生对话。
- 读入材料（代码、文档、配置、输出）保留为路径，而不是
  内容：短关键片段（关键行、值）可能是内联的，但是
  任何更长的内容都会被记录为确切的路径加上一行内容
  是什么以及为什么它很重要——当
  由于复制的文本已过时，因此再次需要内容。
- 一旦检查站着陆，这是主线转弯的唯一痕迹
  上下文看到：原始文本只能通过expand_turn恢复
  回忆（或通过重新阅读文件），每次都会花费令牌和时间。保留
  无论未来的转折可能会引用、验证或继续——
  现在保留的线路比以后召回要便宜。
- 刚刚打开当前回合的消息只是一个提示（镜头，
  不是一项任务：还没有想清楚，真正的思考是在之后开始的
  总结

地）并且不属于替换跨度的一部分。
- 开始转弯的消息永远不是检查点的一部分：它
  在检查点之前逐字保留在表面上，因此复制它
  进入摘要只会重复它。 （对于恢复或恢复的
  转弯其起始消息不再出现在表面上，将其再现为
  第一个 <user-steer>...</user-steer> 元素。）
- 压缩行为本身（compact_turn 调用、节点计数、
  替换结果）是暂时的基础设施：它永远不会出现在
  检查点或回复 - 替换落地后，仅压缩
  内容仍在视图中。
- 可重用过程通过名称（技能或脚本路径）引用
  被重述；这些步骤存在于按需加载的技能中。

## 安装

来自GitHub：

    dsh 插件 --profile web 添加 github:vilicvane/dsh-plugin-turn-memory

从本地目录（开发）：

    dsh 插件 --profile web 添加链接:/path/to/dsh-plugin-turn-memory

然后将插入行附加到配置文件的 cordis.patch.yml 中：

    - 插入：
        - id: 转动记忆
          名称：dsh-plugin-turn-memory

重新启动配置文件应用程序以加载插件。目录链接注意事项：
插件依赖@deepseek-ai/dsh-tools；在插件内运行 pnpm install
目录一次，以便解决依赖性。 git/npm 安装解析
通常依赖。
