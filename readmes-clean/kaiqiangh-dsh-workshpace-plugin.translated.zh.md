# DSH 工作区插件

DSH Workspace 将 `Workspace` 选项卡添加到本地 DeepSeek Harness Web UI。它允许您检查代理接触的内容、查看只读子代理跟踪条目、查看会话工件、预览有限内容、检查 Git 更改、管理受治理的本地工作区内存以及查看代理创建的内存建议 - 所有这些都无需离开对话。

## 它的用途是什么

当代理工作时，利用会话可以生成有用的文件和状态，但该信息不应占据聊天布局。该插件使工作区体验保持紧凑和会话感知：

- 对话视图行中 `Trajectory` 旁边的 `Workspace` 选项卡（唯一条目）；
- 现有工作区选项卡上方的只读 `Sub-agent Trace`，具有有界后代树和选定子项详细信息；
-“工作空间”选项卡顶部的会话摘要块，显示代理所接触的内容（按类型、工件、内存/决策计数、活动范围划分的文件）——按需导出，因此它对于实时会话和重新打开的会话的工作方式相同；
- 选项卡式表面：共享视觉系统上的 `Artifacts`、`Memory` 和 `Git`（自动刷新、友好的空/错误状态、键盘可操作）； Git 选项卡包含“更改”和“历史记录”视图；
- 工件预览（按类型分组、可搜索、每个项目的大小、修改时间、状态和一键下载、复制路径），包括只读多选项卡预览、渲染相关图像和美人鱼图的 Markdown 预览以及流式 PDF 预览；内存治理控制和可读的 Git 检查保留在表面内；
- 内存会在每个会话中自动写入派生事实，因此导出会携带有用的信息；
- Git：存储库状态标头（分支、脏/干净、暂存/未暂存/未跟踪计数、提前/落后）、分组为暂存/未暂存/未跟踪部分的更改，具有可过滤状态和可读的统一/拆分差异，以及提交历史记录（提交列表+每次提交文件/差异）；非 Git 工作区显示干净的“不是 Git 存储库”状态；
- 表面使用范围样式，因此它们不会全局更改 Harness shell；
- 所有显示的副本都有英文和中文版本，并遵循 Harness 应用程序语言（浏览器语言只是备用语言）。

## 安装插件

从这个存储库构建插件：

```sh
npm install
npm run build
```

使用本地 Harness 结账注册构建的插件。从 Harness 项目目录运行此命令，或调整检出此存储库的相对路径：

```sh
dsh plugin --profile web add ../dsh-workshpace-plugin
```

该命令将 Web 插件注册存储在本地 Harness 配置文件中。

## 启动网络用户界面

```sh
dsh web
```

在浏览器中打开【http://127.0.0.1:3080/ZXQ15QXZ。重建插件后重新启动 Web UI，以便加载最新的包。

对于源更改，请运行 `npm run build`，停止当前的 `dsh web` 进程，然后再次启动 `dsh web`。仅当插件注册或链接路径发生变化时才重新运行`dsh plugin --profile web add ...`；重建链接的插件只需要重新启动 Web。

## 使用工作区

1. 打开 Harness Web UI 并选择一个模型。
2. 选择或创建 Workspace 支持的会话。
3. 开始对话并让代理创建或检查文件。
4. 打开 `Workspace` 对话选项卡。
5. 检查选项卡上方的 `Sub-agent Trace` 以跟踪本地会话支持的子代理；不可用或腐败的孩子仍然被贴上标签，而不是显得空虚。
6. 使用选项卡：
   - `Artifacts` — 检查会话创建的可交付成果（按类型分组，可按名称搜索），并在列表旁边提供有限预览、每个项目的大小、修改时间、预览状态、复制路径和一键下载；
   - `Memory` — 审查、创建、验证、固定、存档或忘记项目/会话内存记录，审查代理建议（`model-suggested` 项目显示为未验证，直到您验证或拒绝它们），并查看自动编写器从代理活动中得出的会话事实；
   - `Git` - 仓库状态标题（分支 + 短头、脏/干净、暂存/未暂存/未跟踪计数、提前/落后），然后是 **更改/历史** 开关：更改显示工作树和暂存更改（自动刷新，分组为暂存/未暂存/未跟踪部分，可按状态过滤），带有彩色、行号统一差异、`+N −M` 统计信息和复制差异控制；历史记录显示提交列表和每个提交的文件/差异详细信息。

“工作空间”选项卡以具有范围样式的基于卡片的布局呈现三个表面；选项卡上方的摘要块跟踪相同的会话事实。

## 故障排除

- **工作空间选项卡丢失：**重建插件，重新启动`dsh web`，如果在构建之前创建了本地配置文件，则再次添加插件。
- **旧的浮动面板仍然可见：**旧的 Web 进程正在为缓存的包提供服务；停止它并再次运行 `npx @deepseek-ai/dsh web`。 v0.2 中删除了右下角多余的药丸——“工作空间”选项卡是唯一的条目。
- **v0.6 之前创建的历史会话不会重新打开：** v0.6 之前的版本将自定义 `workspace/summary` 事件持久化到会话日志中，并且 DSH 的冷持久化路径拒绝加载包含未知的不可忽略事件类型的日志。 v0.6 停止保留该事件，因此新会话是干净的并可以正常重新打开；已受影响的日志无法安全地重写（序列连续性），因此这些特定会话不可恢复 - 删除它们或启动新会话。
- **Markdown 图像或美人鱼图不显示：** 该插件通过同源不透明资源路由和供应商捆绑包为它们提供服务；如果 Web UI 在 v0.6 重建之前启动，请重新启动 `dsh web`，以便注册新路由（`/workspace/vendor/mermaid.js`、`/workspace/resource` 上的 Range/ETag）。
- **工件或内存为空：**从活动的 Harness 会话中打开工作区；表面读取会话范围的数据而不是全局文件列表。
- **Git 显示“不是 Git 存储库”：** 工作区根不是 Git 签出。从工作目录为 Git 存储库的会话中打开 Workspace，以查看更改和历史记录。
- **内存导出下载一个空包 (`"records":[]`)：** 仅当会话没有内存且没有代理文件活动时才会出现这种情况。从 v0.2 开始，会话自动编写器从代理工具活动（按类型+工件的文件）中派生 `fact` 记录，因此活动会话即使没有手动记录也会导出有用的事实。手动记录在 UI 中创建或由代理通过 `workspace_memory_propose` 建议；提案将存储为 `unverified`，直到您验证它们为止。存储详细信息：[`docs/MEMORY_STORAGE.md`](docs/MEMORY_STORAGE.md)。
- **该命令找不到插件：** 从 Harness 项目运行 add 命令并使用此存储库的正确相对路径。
