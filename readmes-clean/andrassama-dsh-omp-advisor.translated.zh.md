# 区议会

> **顾问指南。病房保护。模型执行。**
>
> *包名称：`dsh-omp-advisor` — 安装和存储设置的名称。*

## 这是什么？

您的编码代理很好，但在长时间的会话中，它可能会出现视野狭隘：错过安全漏洞，在测试实际通过之前声称“已完成”，或者在错误的转弯后继续前进。 **选区委员会**为其提供了第二双眼睛——一个或多个独立的“顾问”模型，他们实时观看会议并在有问题时大声疾呼。

每个顾问都会随着记录的增长而阅读它，可以使用只读工具（`read` / `grep` / `glob`）调查您的工作空间，并通过专用的 `advise` 工具提供具体建议。建议以清晰标记的形式到达，主要代理*权衡*——而不是它必须遵守的命令：

```
<advisory advisor="The Red Teamer" severity="concern" guidance="weigh, don't blindly obey">
  The SQL in search.py interpolates the user query directly — parameterize it before this ships.
</advisory>
```

您可以从 DSH 的模型列表中选择每个顾问的模型，将其范围限定到特定工作区，并为其指定角色（包含 25 个预设）以及精选的领域技能（打包的 250 个）。它是来自 [can1357/oh-my-pi](https://github.com/can1357/oh-my-pi)] 的顾问看门狗设计，在 [DeepSeek Harness](https://github.com/deepseek-ai/dsh) (DSH) 插件接缝上原生重建。

```
primary agent ──► session log ──► delta renderer ──► advisor model (your pick from the DSH model list)
      ▲                                                     │ read/grep/glob (read-only)
      │                                                     ▼
      └──── agent.inject / agent.steer ◄── advise tool ── dedupe + quarantine
```

## 概览

- **实时审查** - 顾问审查记录的每个新部分（每轮或每步），并且永远不会重新阅读历史记录两次。
- **建议，而不是命令** - 注释带有严重性（`nit` / `concern` / `blocker`）和指导*“权衡，不要盲目服从”*；主要代理人决定做什么。
- **持久记忆** - 顾问通过可插拔引擎（纯文本 MD、OpenViking、Hindsight、MisakaNet、mem0 或任何 MCP 服务器）在每次审核中回忆相关课程，并写回持久的课程。
- **Git 恢复点** — 轮流边界处的无副作用工作区快照让顾问可以推荐精确的、仅限工作树的倒带。
- **完成门** - 在代理声称“完成”*之前，顾问会验证最初的要求是否已实际实施，并要求提供诚实的报告。
- **弹性** — 自动重试失败的审核和轮次、配额冷却、输出隔离；顾问永远不会阻止您的代理人。
- **25 个角色，250 种技能** — 从安全审核员到网络小说架构师的一键预设，每个角色都具有精心策划的领域技能。
- **多选项卡设置 + 实时监视器** — 常规/顾问/工作区/内存/监视器，以及可选的工作区范围侧边栏选项卡。

## 它是如何工作的

### 审核循环

- **增量评论。** 顾问永远不会两次看到整个历史记录：持久会话日志上的光标会将每个新切片（`user/message`、`assistant/message`、`tool/call`、`tool/result`）呈现为紧凑的降价*更新*顾问模型评论。
- **微小增量跳过（可选）。** 设置 **跳过微小增量** 后，小于阈值的转录本更新将被跳过，而不调用顾问模型 - 这是一种在闲聊会话中减少顾问流量的廉价方法（跳过的增量稍后不会重播）。

### 建议和交付

- **建议，而不是命令。** 注释到达时为
  `<advisory advisor="…" severity="…" guidance="weigh, don't blindly obey">…</advisory>`
  消息。主要代理决定如何处理它们。
- **严重性。** `nit`（默认）·`concern`·`blocker`。升级级别重复数据删除：相同的注释仅以严格更高的严重性重新传送。
- **交付渠道（DSH-native）。**

### 严重性 · 主要运行 · 主要空闲
- **严重性**：非中断（默认：`nit`） · **主要运行**：`agent.inject` — 运行下一步边界，永不唤醒 · **主要空闲**：`agent.inject`
- **严重性**：中断（默认：`concern`、`blocker`） · **主要运行**：`agent.steer` — 最近的步边界 · **主要空闲**：`concern` 降级到 `inject`； `blocker` 仍在转向（可能会唤醒转弯）

- **中途延迟。** 使用 `reviewTrigger: step`，在轮次仍在运行时提出的非阻塞注释将在轮次完成时确定性地保留和刷新，因此部分工作不会中断，也不会丢失任何建议。
- **合并（可选）。** 在有多名顾问的情况下，注释可以快速连续地落地。将**合并建议**设置为以毫秒为单位的窗口（例如 `1500`），运行时缓冲来自该窗口的*所有*顾问的注释，然后将它们作为**每个传递通道一条多 `<advisory>` 消息**而不是每个注释一条消息发出。语义：
  - `0`（默认）— 每个音符均单独传送，与上述完全相同。
  - 窗口活动 - 计时器从第一个缓冲音符开始；当它触发时，批次在发出时按通道分组（转向与注入根据主节点的*当前*状态重新解析）并作为每个非空通道的一条消息发送。
  - 中断严重性 — `concern`/`blocker`（根据您的中断集）**立即刷新整批**，因此紧急建议永远不会等待窗外。
  - 会话处置取消计时器并删除缓冲的注释：处置的会话永远不会收到建议。

＃＃＃ 弹力

- **自动重试（可选，默认开启）。** 故障会自动恢复，而不是默默地消失：
  - 顾问审核失败（速率限制、暂时性提供商错误）会在配置的延迟后重新运行*相同的增量，直至配置的尝试上限。
  - 失败的**主模型转弯**（`turn/end` 和 `reason.kind: "error"`）在相同的延迟后收到自动“从上次停下的地方继续”后续消息，受每个失败事件的限制并由任何已完成的转弯重置。
  - 尝试上限：`1–999`，或 **`0` = 无限制**（消息标记上限为 `∞`）。用户中止和永久错误（未知模型/提供商）永远不会重试 - 即使有无限上限。通过 **自动重试失败** 关闭整个功能。
- **遏制（移植）。** 输出隔离（不可用工具请求、仅输出破坏性指令）、3 次连续失败积压下降、永久错误停止直至设置更改、配额/速率限制冷却暂停。顾问**永远不会阻止主要代理**——这是故意的、更安全的偏离 oh-my-pi 的追赶等待。
- **上下文溢出恢复 (v0.7.3)。** 如果 Advisor 累积的历史记录超出了模型的上下文窗口，则运行时会重置该 Advisor 的对话（将其缩小回系统提示符 + 当前增量）并重试一次 - 而不是在无限重试循环中重新发送相同的臃肿上下文。第二次溢出（单个增量本身太大）会停止顾问程序，而不是永远旋转。然后，监视器会显示停止原因以及 **Resume** 按钮 (v0.7.4)：将 Advisor 切换到 Advisors 选项卡中的更大上下文模型，然后单击 Resume 将其直接恢复 - 无需重新启动。

### 干预

- **阻止程序干预（可选，默认关闭）。** DSH 不会向插件公开同步预工具调用否决权，因此这是平台允许的最强中断：当顾问在主代理 **运行** 时引发 `blocker` 时，插件在运行步骤上调用 `agent.cancel` - 工具调用尚未分派中止，已经运行的调用提交 - 然后用建议作为后续操作唤醒代理，以便它看到原因并可以做出反应。使用审查触发器 `step`，这会落在步骤之间，即在模型可以发出“下一个”破坏性调用之前；当前步骤中的快速工具可能会首先完成。选择加入**阻止者干预**；没有它，建议就只是建议。

### Git 恢复点

- **Git 恢复点（可选，默认关闭）。** 该插件将工作区快照为**无副作用的 git 对象** - 一次性索引捕获跟踪的更改*和*未跟踪的文件（尊重 `.gitignore`），作为提交对象存储在隐藏命名空间 `refs/dsh-omp-advisor/**` 下。您的索引、HEAD、分支和工作树永远不会被触及，也不会运行任何重置/清理/存储命令。快照发生在转弯边界和（可选）**在改变工具之前**通过直通 `fs/write-intent` / `fs/edit-intent` / `tools/pre-execute` 侦听器，具有有限的等待，永远不会阻塞您的工具。顾问获得只读 `list_restore_points` / `diff_restore_points` 工具；在执行破坏性或错误步骤后，顾问程序可以使用 `rewindTo` 调用 `advise` — 该顾问程序随后会携带精确的仅工作树恢复配方 (`git restore --source=<sha> --worktree --staged .`) 以及顾问程序的分类：**哪些步骤不能再次发生，哪些步骤是程序化的
