## 关于

DSH 插件目录是社区驱动的 DeepSeek Harness 插件目录。该存储库处理提交和验证过程 - 插件作者提出一个问题来提交他们的插件，并自动检查验证其结构。这里的受理记录文件是导出的快照，供参考。该存储库不托管插件源代码或二进制文件。

接受的插件会在目录中获得更显着的位置，使用户更容易找到它们。

## 它是如何工作的

插件作者和社区成员使用 GitHub 问题表单提交**每个问题一个插件包**。

### 必填字段 · 需要提供什么
- **必填字段**：包 URL · **提供什么**：指向默认分支上的包目录的 GitHub URL - 存储库根目录或类似 `/tree/main/my-plugin` 的路径。
- **必填字段**：主要类别 · **提供什么**：线束类别列表中的一个类别。
- **必填字段**：描述 · **提供什么**：描述插件功能的单个事实句子。
- **必填字段**：安装命令 · **提供什么**：从插件自己的文档复制的一行安装命令。

![插件提交验证工作流程](assets/submission-workflow.png)

自动检查读取问题字段并验证提交的信息和包结构。上游存储库仍然是插件本身的真实来源。

## 什么可以通过验证

验证适用于可公开访问、可安装的 DSH 配置文件包 — 在其 `package.json` 中声明 `dsh.bundle.patch` 的包。

### 规则 · 通过 · 不通过
- **规则**：存储库访问 · **通行证**：存储库是公共的。 · **未通过**：存储库是私有的或无法访问。
- **规则**：包 URL · **传递**：指向当前默认分支上的确切包目录。 · **不通过**：指向文件、错误目录或非默认分支。
- **规则**：包清单 · **通过**：`package.json` 直接位于提交的目录内。 · **未通过**：`package.json` 丢失或位于其他地方。
- **规则**：捆绑声明 · **通过**：`package.json` 声明 `dsh.bundle.patch`。 · **未通过**：软件包仅声明 `dsh.client` 或没有捆绑补丁。
- **规则**：补丁文件 · **通过**：声明的补丁文件存在于包目录中。 · **不通过**：声明的补丁文件丢失或位于包目录之外。
- **规则**：列出详细信息 · **通过**：包括有效类别、事实单行描述和记录的单行安装命令。 · **未通过**：任何必需的值缺失、无效、促销或无证。

仅声明 `dsh.client`（不含 `dsh.bundle.patch`）的软件包不是可安装的配置文件包，也不会通过验证。这些检查仅验证结构和列表详细信息 - 它们不测试运行时行为、质量、兼容性或安全性。请参阅 [CONTRIBUTING.md](CONTRIBUTING.md) 了解完整的提交要求。

## 信任和安全

目录检查仅验证提交是否具有预期的结构。他们不运行插件或执行其安装命令 - 安装命令仅以纯文本形式存储。

列入目录并不表示任何形式的安全审核、认可或保证。列表并不意味着该插件是安全的、兼容的或经过批准的。提交存储库并不建立它的所有权。

在安装任何第三方插件之前，请检查其源代码、权限、依赖项、许可证和文档。
