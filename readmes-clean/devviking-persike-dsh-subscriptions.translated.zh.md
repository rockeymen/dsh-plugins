#dsh-subscriptions

使用您自己的 **Claude** 和 **ChatGPT/Codex** 订阅作为 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 中的模型提供程序 — Claude Code 和 Codex CLI 使用相同的 OAuth 登录。没有 API 密钥。

## 安装

```bash
dsh plugin --profile web add github:DevViking-Persike/dsh-subscriptions
```

重新启动 `dsh`，然后登录到您拥有的任何订阅：

```
http://127.0.0.1:1458/claude/start
http://127.0.0.1:1458/codex/start
```

每个都会打开供应商自己的登录页面并在本地存储生成的 OAuth 凭据。代币自行刷新；您登录一次。

### 路由·提供商·凭证
- **路由**：`claude` · **提供商**：`claude-code-oauth` · **凭证**：`~/.dsh/claude-code-oauth.json`
- **路由**：`codex` · **提供商**：`codex-oauth` · **凭证**：`~/.dsh/codex-oauth.json`

其他端点：`GET /<route>/status` 报告订阅是否已连接以及其令牌何时过期； `POST /<route>/logout` 删除凭证。服务器仅绑定到环回。

## 配置

每个字段都是可选的。

### 字段·默认值·含义
- **字段**：`routes` · **默认**：`['claude', 'codex']` · **含义**：要安装哪些订阅。
- **字段**：`controlPort` · **默认**：`1458` · **含义**：登录端点的环回端口。
- **字段**：`claudeModels` / `codexModels` · **默认**：发货目录 · **含义**：提供的数组 **替换** 默认值。
- **字段**：`claudeCredentialPath` / `codexCredentialPath` · **默认**：在 `~/.dsh` 下 · **含义**：存储每个凭证的位置。
- **字段**：`claudeImportFrom` / `codexImportFrom` · **默认**： — · **含义**：从 CLIProxyAPI 身份验证文件播种一次。
- **字段**：`streamIdleTimeoutMs` · **默认**：`300000` · **含义**：传输放弃之前读取之间的预算。
- **字段**：`defaultContextWindow` · **默认**：`200000` · **含义**：为目录中不存在的模型假设的上下文。
- **字段**：`maxTokens` · **默认**：`32000` · **含义**：当请求或目录均未指定时，输出上限。
- **字段**：`retryPolicy` · **默认**：正常，重试 3 次 · **含义**：在默认值上合并。

```yaml
- id: dsh-subscriptions
  name: 'dsh-subscriptions'
  config:
    routes: ['claude']
    controlPort: 1458
```

## 模特经历

对模型透明：插件注册提供者路由并流响应，不添加任何工具、提示部分或上下文。

它影响的是计费，两条路由故意**不同意**：

- **Claude** 报告 `input_tokens` 已经排除了缓存读取，因此没有减去任何内容。
- **Codex** 包含它们，因此将它们减去以保持计数不相交。

这两个方向都由从线束自身实现中记录的测试来固定，因为任何一个向后都不会产生任何影响——它只是错误地报告了每个成本显示中的上下文。

两条路线均仅发送短信。在发送请求之前，图像内容会被拒绝，因为序列化路径会丢弃它，并且模型会回答它从未见过的问题。

## 安全

- 使用仅限所有者的权限（`0600`，父级 `0700`）以原子方式写入凭证，并通过 **跨进程写入器锁** 读取文件。两个 DSH 实例同时刷新不会损坏文档或两次烧毁刷新令牌 — 通过分叉真实进程的测试证明，当锁定被移除时，负面控制会失败。
- 令牌绝不会出现在错误消息、日志行或 `/status` 响应中。上游错误主体在引用之前经过编辑。
- 刷新失败不会影响存储的凭据，因此短暂的中断无法强制重新登录。
- 截断的流会引发 `STREAM_CLOSED`，而不是呈现为完成的响应。
- 过时的锁永远不会被盗：文件年龄不能证明其所有者已死亡，因此孤儿恢复仍然是操作员的操作。

## 已知限制和延期工作

- **构建版本敏感。** 该插件位于线束存储库之外，这表明它在首次发布之前不做出兼容性承诺。因此，块词汇表在加载时进行验证，并且不匹配拒绝与命名漂移字段的消息一起安装。
- 登录回调绑定 `127.0.0.1`，而供应商注册的重定向 URI 为 `localhost`。在 `localhost` 首先解析为 `::1` 的主机上，浏览器回调将不会到达。这些端口由公共客户端固定，无法重新配置。
- 模型目录是静态配置，不是从供应商发现的。您的订阅提供服务但目录省略的模型在显式命名时仍然有效，并使用默认上下文窗口进行解析。
- 没有图像输入，Codex 路由拒绝停止序列 - Responses API 没有等效项，默默地删除一个将使模型运行超过调用者所依赖的边界。
- 测试套件完全针对本地 `node:http` 服务器运行。它证明了这个插件的行为，而不是任何一个供应商仍然完全讲这种方言：夹具对线束对电线的信念进行编码，从其自己的实现中记录下来。
